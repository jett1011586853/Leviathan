# GameModel Game-JEPA 研究与工程方案

## 1. 研究范围

本阶段只研究《逆战：未来》的“丛林魅影”地图，不声称泛化到其他地图或游戏。目标是在现有 GameModel 的 WGC 捕获、可信 observation、时序世界状态和输入租约之上，增加一个可离线训练、可回放评测、可逐级放行的预测式世界模型。

当前实现已经具备 60 FPS 窗口捕获、录像、低频采样帧、可信来源校验、观察态 ROI 感知和确定性数据集。当前没有足够的人工真值、动作同步轨迹或跨局测试集，因此本阶段先训练表示和预测，不直接开放实时自动战斗。

## 2. 核心假设

Game-JEPA 不在像素空间生成下一帧，而是在潜在表示空间预测未来状态。该选择参考 I-JEPA 的“从上下文预测目标表示”和 V-JEPA 2 的“无动作视频预训练 + 少量动作条件适配”路径。

研究假设分为三层，必须逐层验证：

1. **H1：视频表征有效。** 无动作的“丛林魅影”视频能提升阶段、HUD、目标和场景位置等下游任务的线性探测或轻量微调效果。
2. **H2：动作预测有效。** 在同步记录键鼠动作后，动作条件潜在动态模型能比无动作基线更准确地预测短时未来状态。
3. **H3：规划有效。** 仅当 H1/H2 成立后，模型预测控制才能在离线回放和影子模式中降低偏航、空枪、补给遗漏或危险暴露。

公开视频只能用于 H1。没有同步动作的视频不能作为 H2/H3 的因果控制真值；逆动力学产生的伪动作必须标记为 `pseudo`，不能进入最终测试真值。

## 3. 系统结构

```text
                         离线训练面
公开视频 / 本机录像 / 动作轨迹
        -> 来源与授权目录
        -> 去重、切片、质量门控
        -> 按来源/局次分组划分
        -> Game-JEPA 无动作预训练
        -> 动作条件潜在动态模型
        -> 结构化状态头与离线评测
        -> 版本化模型包

                         在线执行面
WGC 60 Hz -> 轻量感知/跟踪 20-30 Hz -> 世界状态融合 10-20 Hz
         -> 潜在未来滚动 5-10 Hz -> 约束规划器 5-10 Hz
         -> 租约控制器 60 Hz -> 键鼠输入
         -> watchdog / 前台锁 / 超时释放
```

主 Agent 只负责目标、配置、会话、模型版本和复盘。大模型不进入逐帧控制循环。实时 Sidecar 继续负责高频感知、规划和输入安全。

## 4. 虚拟空间表示

“虚拟空间”不是完整 3D 重建，也不是生成式视频。它是显式状态与潜在残差的混合表示：

| 状态块 | 内容 | 监督来源 |
| --- | --- | --- |
| ego | 相机运动、朝向变化、移动状态 | 光流、键鼠动作、回放标注 |
| topology | 场景位置嵌入、路口/房间/补给点拓扑 | 人工地图资产、地点标注 |
| occupancy | 近场可通行区域和障碍置信度 | 视频几何、人工复核 |
| entities | 敌人、弱点、威胁和轨迹 | 检测/跟踪标注 |
| resources | 血量、弹药、经济、补给与升级状态 | HUD 标注/OCR |
| objective | 阶段、任务箭头和当前子目标 | 阶段/导航标注 |
| latent | 难以显式标注的视觉动态残差 | JEPA 自监督目标 |
| uncertainty | 各状态块置信度、分布外分数 | 校准集、集成或预测残差 |

规划器只能使用通过能力门控的字段。低置信度或过期状态触发减速、停止射击、释放输入或回到观察态，不能由潜在向量绕过安全策略。

## 5. 数据分层

### 数据规模硬门槛

Pilot tokenizer 固定为 8 帧/4 秒、112x112、16x16 patch 和 2 帧 tubelet，即 196 token/片段、49 个唯一视频 token/秒。正式预训练集要求：

- train：至少 50,000,000 个去重后时空 token，约 283.4 小时唯一视频；
- validation：至少 6,250,000 token，约 35.4 小时；
- test：至少 6,250,000 token，约 35.4 小时；
- 总计：至少 62,500,000 token，约 354.3 小时唯一视频。

重叠窗口、数据增强和重复 epoch 不增加“唯一 token”计数。训练集至少需要 50 个独立内容组，单一内容组最多贡献训练 token 的 2%；validation/test 各至少 10 个独立内容组。达到 token 数但未达到来源多样性门槛时，数据集仍不允许作为正式实验集。

### A. 公开视频语料

- 用途：动作无关的视频表征预训练、场景地点聚类、阶段预训练。
- 要求：保留页面 URL、平台、作者、发布日期、许可证/授权状态、查询词、文件哈希和时间范围。
- 限制：默认只建立元数据目录。只有用户拥有、公共领域、明确许可或兼容许可证的内容才自动下载。

### B. 本机同步轨迹

- 用途：动作条件世界模型、控制结果预测、离线策略评测。
- 内容：WGC 时间戳、帧、键鼠动作、输入租约、HUD/阶段状态、会话/局次 ID。
- 要求：动作时间戳和图像使用同一单调时钟；人工接管、菜单、暂停和丢帧必须显式标记。

### C. 人工复核评测集

- 用途：验证集、测试集和最终能力门控。
- 要求：来源与训练集隔离；测试集标签冻结；模型预标注必须经人工复核才能成为真值。

## 6. 防止数据泄漏

不能随机按帧划分。相邻帧高度相似，同一公开视频的不同切片也可能是重复内容。

固定规则：

1. 以 `content_group_id` 为最小划分单位，默认等于原始视频或游戏局次 ID。
2. 同一源视频、镜像视频、剪辑重传和同一连续局次只能进入一个 split。
3. 先做文件哈希和视频指纹去重，再做 80/10/10 的组级确定性划分。
4. 测试集优先按时间、作者或采集批次留后，避免仅记住 HUD 皮肤和固定路线。
5. 任何 split 变更都生成新的数据集版本和审计报告。

## 7. 训练阶段

### P0：数据与基线

- 建立来源目录、授权门控、视频探测、切片和组级划分。
- 复用现有 5 分钟本机录像跑通工程链路。
- 建立恒等、上一状态、匀速外推和现有 ROI 规则基线。

### P1：Game-JEPA 无动作预训练

- 输入：8-16 帧短片段，112-224 像素训练分辨率。
- 编码器：时空 tubelet embedding + Transformer。
- 目标编码器：在线编码器的 EMA 副本。
- 目标：预测被遮挡时空区域的目标潜在表示，使用归一化潜在回归损失。
- 评测：冻结编码器的阶段/地点线性探测，少量标签下的目标与 HUD 头。

### P2：动作条件潜在动态

- 输入：潜在状态、键盘状态、鼠标增量、射击/交互动作和时间间隔。
- 输出：多个未来时距的潜在状态与显式状态变化。
- 评测：潜在预测误差、事件 F1、轨迹偏差、置信度校准和不同预测时距退化曲线。

### P3：规划与影子模式

- 使用候选动作序列在潜在模型中滚动，代价函数包含目标进度、生命风险、弹药、瞄准误差、动作平滑度和不确定性。
- 首选 CEM/MPC 或小型候选集，不让 LLM 逐帧选动作。
- 先只记录“本应执行的动作”，与人类轨迹比较；通过门限后才进入受限 live。

## 8. 评测和放行门

| 层级 | 指标 | 最低要求 |
| --- | --- | --- |
| 数据 | 授权覆盖、重复率、split 泄漏 | 测试集零跨组泄漏；所有文件可追溯 |
| 表征 | 线性探测、少样本微调 | 明显优于随机初始化和单帧编码器 |
| 动态 | 多时距预测、事件 F1、ECE | 优于恒等/匀速/无动作基线 |
| 规划 | 离线回放代价、影子动作偏差 | 不确定性升高时能主动保守 |
| 实时 | P50/P95 延迟、掉帧、输入释放 | 决策超时或失焦时立即释放输入 |

不预设虚构数值。门限必须在首批复现实验后依据真实分布冻结，并在测试集评测前写入版本化配置。

## 9. 8 GB GPU 约束

当前开发机为 RTX 4060 Laptop 8 GB。默认 pilot 使用 112x112、8 帧、192 维、4 层编码器、混合精度和梯度累积。较大模型在稳定数据管线和基线成立后再扩展，不以显存占满作为研究目标。

## 10. 与现有 GameModel 的集成边界

训练工程位于 `training/gamemodel_jepa`，不直接依赖主 CLI 进程。模型包需要包含配置、权重哈希、训练数据集 ID、代码版本、指标和能力声明。只有通过回放评测的能力才可由 Sidecar 加载；未验证能力保持观察态。
